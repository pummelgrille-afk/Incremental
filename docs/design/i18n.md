# Localization

Source of truth for how text gets on screen. Established in Phase 44, which
found 264 sentences typed into templates and 278 more authored in `content/`,
none of which could be changed without editing a component.

The brief in `PLAN.md` is unusually specific about *why*: externalize the text,
build a pipeline so a language can be added **post-launch based on your own
audience data**, and QA overflow. That third clause is the one that shapes
everything here — a pipeline nobody has exercised is a guess, so this phase
ships a language and runs the game in it.

---

## 1. The two halves

Text lives in exactly two places, and which half a string belongs to is not a
judgement call.

| | Chrome | Content |
|---|---|---|
| Is | Labels, buttons, banners, hints | Names and descriptions of units, zones, stages, nodes, achievements, cards |
| Authored in | `src/lib/i18n/en/*.ts` | `src/lib/content/*.ts`, beside the tuning |
| Keyed by | A written key, `hud.paused.title` | The thing's own id, `platform.bolt.name` |
| Checked by | The compiler — `MessageKey` is `keyof typeof EN` | `tests/i18n.test.ts`, against `contentSources()` |
| Translated by | A locale's `messages` | A locale's `content` |

**Content English stays in `content/`** because `CLAUDE.md` says content is
typed data and a Platform's name belongs next to its attack and its interval.
Moving 140 names into the catalogue would have bought type-checked keys at the
price of turning every content file into a list of ids. A translation overrides
by key instead; the authored English is the fallback.

**Both fall back per key, not per file.** A locale that has translated the
chrome and none of the units is a playable game in that language with English
unit names — not a broken one, and not a blocked release.

## 2. Writing a message

```ts
'formation.level-up': 'Level up for {cost} Clearance',
```

- **A number inside a sentence is a `{placeholder}`, never a concatenation.**
  `'Level up for ' + cost + ' Clearance'` cannot survive a language that puts
  the number last, and most of them do something we did not plan for.
- **Placeholder names are for humans**: `{cost}`, `{ring}`, `{seconds}`. A
  translator moves the hole; they never rename it.
- **`key` and `values` are reserved.** `T.svelte` takes those as its own props,
  so a `{key}` hole could never be filled. Checked.
- **There is no escape for a literal brace.** An escape nobody needs is a rule
  every translator has to be told about, so an unmatched brace is always a typo
  and the test says so.

### Plurals

```ts
'rewind.kept.zones.one': '{count} zone unlocked',
'rewind.kept.zones.other': '{count} zones unlocked',
```

Called as `plural('rewind.kept.zones', n)`, which asks `Intl.PluralRules` for
the active locale. English has two forms and would have let `n === 1 ? '' : 's'`
stand; a language with six would not, and by then the fix would have been in
forty files. `.other` is the form that may never be missing — every unauthored
category lands on it.

### A sentence with markup in it

```svelte
<T key="hud.paused.next">
  {#snippet pause()}<Kbd>{key('pause')}</Kbd>{/snippet}
  {#snippet escape()}<Kbd>{key('menu')}</Kbd>{/snippet}
</T>
```

`ui/T.svelte` fills each hole with a snippet named after it. The alternative was
cutting the sentence into three keys around the markup, which hands a translator
two fragments and a word order they cannot change.

It lives in `ui/` rather than `ui/primitives/` because it reads the current
language from `stores/`, and a primitive may not (`ui-spec.md` §3). There is
exactly one of it.

## 3. Reaching the language

```
i18n/en/*.ts     the English catalogue, split by surface
i18n/en.ts       composes them; defines MessageKey
i18n/parts.ts    a message → literal runs and holes
i18n/translate.ts   look up, fall back, fill        ← plain functions
i18n/locales.ts     which languages exist
i18n/pseudo.ts      the QA language, as a rule
i18n/budgets.ts     slots that cannot grow
i18n/contentSources.ts   every content string, with its key
stores/i18n.svelte.ts    the one rune                ← the only Svelte
ui/T.svelte              markup inside a sentence
```

Every function in `translate.ts` comes in a pair: `translateIn(locale, …)` and
`translate(…)`. The first is the real one — `stores/i18n.svelte.ts` passes the
locale it holds in a rune, so **the locale is an argument** and Svelte tracks it
like any other dependency. The bare form reads a module-level variable and
exists for callers with nothing to be reactive to; `core/save.ts` building an
`Error` is the only one. A component that called it would render the right words
once and never change language. Checked.

**Nothing under `progression/` or `core/` may name anything.** Neither knows
which language is on screen, so a projection that carries copy makes the
component that renders it unable to translate. `TRACK_COPY` in
`progression/support.ts` was the last of those and is gone; the view carries the
track's id and the editor looks the words up. Checked.

## 4. The QA language

`qa` — "⟦Ƥŝéüðø⟧" — ships in every build. It is **a rule, not a table**: a
`transform` on the locale, applied to the English source at lookup time, in the
same sense as the starfield and the score (`art-style.md` §8). It therefore
covers all 542 strings including the 278 in `content/`, and cannot fall out of
step with any of them.

It does three jobs at once:

1. **It expands**, hardest on the shortest strings — the shape real translation
   takes, because a six-letter label has no redundancy to spend and a paragraph
   has forty words of it.

   | English length | Assumed growth |
   |---|---|
   | ≤ 10 | +100% |
   | ≤ 20 | +80% |
   | ≤ 30 | +60% |
   | ≤ 50 | +40% |
   | 51+ | +30% |

2. **It stays readable.** Latin letters with diacritics, so a tester can still
   tell that the right string is in the right place and spot a sentence that has
   been assembled out of two.
3. **It is delimited**, `⟦…⟧`. A clipped string shows as a missing bracket
   rather than as a judgement call about whether that sentence was meant to end
   there. A string with no brackets at all was never localised.

Placeholders pass through untouched — a pseudolocale that mangled `{count}`
would be testing the interpolator rather than the layout.

## 5. Budgets

Most chrome wraps: a paragraph in a dialog can be twice as long and simply be
taller, and a budget on a slot that wraps is a rule with no failure mode. So
`i18n/budgets.ts` covers only the places where the CSS genuinely refuses to
reflow — `white-space: nowrap`, `text-overflow: ellipsis`, a fixed-width tile.

Each budget is the slot's usable width, at that slot's own font size, over an
average glyph advance of **0.55em**. Worked example, the sidebar tab:

```
tab width the field can spare      ~200px
− horizontal padding (0.7rem × 2)  ~22px
− keycap and gap                   ~34px
= text                             ~144px
÷ (0.72rem × 0.55 = 6.3px/char)    ≈ 22 characters
```

`tests/i18n.test.ts` checks the English **and its pseudolocale expansion**
against each budget. English fitting proves nothing about German; the expansion
is what asserts the slot has room for a translation.

**A failed budget is a question, not an answer.** Three ways out, in order:

1. Let the slot wrap. This is what `Choice` did in Phase 44 — four options of
   nowrap text in a 38rem dialog fit English and nothing else.
2. Shorten the English.
3. Widen the slot.

Raising the number is the one move that is never right. It moves no pixels.

## 6. Adding a language

```bash
npm run i18n:extract -- de Deutsch
```

Writes `src/lib/i18n/locales/de.ts`: every chrome key and every content key with
the English source as its value, in the order a player meets them. Translate in
place.

Then register it — three lines in `locales.ts`:

```ts
import { DE } from './locales/de'
export const LOCALES: readonly LocaleDef[] = [/* … */, DE]
```

Registration is deliberately a separate step. A locale that appeared in the
picker the moment its file existed is a locale a half-finished translation
ships in.

`npm test` then checks the file for orphaned keys, mismatched placeholders,
overrides naming content that has been renamed away, and every budget. Nothing
checks whether the translation is *good*; that is what a reviewer is for.

The extractor runs through Vite rather than plain Node, and pulls in no new
dependency: the catalogue and the content are ordinary TypeScript modules with
extensionless imports, which Node cannot resolve and Vite resolves exactly as
the app does.

### What is deliberately not extracted

- **Contact and boss names.** Ten Contacts and thirteen boss and boss-phase
  names are authored and drawn by nothing — there is no bestiary, the field
  draws sprites, and a boss stage's title on the map is the *stage's* name.
  Extracting them would pay for two dozen strings that cannot appear. They join
  the list the day something draws them.
- **Key labels.** `bindingLabel()` produces "Space", "Esc", "F2". A keycap's
  text is the keyboard's word, not this game's.
- **The diagnostics panel.** Frame times and entity counts behind a setting,
  written for whoever is profiling the build. Marked `<!-- i18n-exempt -->` in
  the source, with the reason.
- **`MigrationError`'s message.** It names schema versions and what refused to
  move between them — a developer's sentence, quoted inside a translated frame.

## 7. The language a player gets

Stored in the save as `settings.locale`, applied by `publishSettings()` in
`bootstrap.ts` like every other setting: the save is the record, and a language
the player can see but that was never persisted is worse than one that did not
change at all.

No schema bump. Validation repairs a save that predates a field by defaulting
it, so an old save loads in English — the language it was played in. A code this
build does not ship falls back rather than showing keys.

**Every language is named in itself and never translated.** A player who has
landed somewhere they cannot read finds their way back by recognising their own
in the list, and "Anglais" does not help them.

There is no automatic detection from `navigator.language`, and that is a
decision rather than an omission: the brief is to add languages from audience
data, and a game that silently switches to a half-finished translation because
of a browser setting reports that data wrong.
